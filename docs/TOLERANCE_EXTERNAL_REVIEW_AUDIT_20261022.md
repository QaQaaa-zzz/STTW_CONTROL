## 一、总体判断与研究主问题

这份评审抓住了重要问题：解析模型的目标与任务标签不同；跨速度代理失效；有限扰动暴露、单训练种子、任务保持不足；目前不足以支持“容扰度指导训练更强”。这些应当接受。

需要纠正的是：本次双网络容扰度训练没有使用V3；不存在已发现的4倍reward-dt错误；采样单测和实际路径族占比已经存在；PPO的奖励截断不等于直接动作梯度消失；二分法和有限oracle不能自动证明真实边界/不可恢复上界。critic失配、暴露不足、引导太弱等是合理解释，尚未被消融识别为原因。

建议主问题收敛为：**在冻结底层的中层控制任务中，方向性恢复余量是否能帮助选择更有效的恢复训练数据，并在相同总交互量下改善实际任务恢复？** 解析模型是待验证的信息来源；经验抗扰改善是目标，不能用余量分数改善代替。单网络α是控制器候选与另一个研究问题，不强行宣称两条线都已完成。

## 三、幅值约束公式：能推什么，不能推什么

若冻结系数模型满足 `zdot=λz+bu+γF(t)`，通过乘exp(−λt)并设终端z(T)=0，得到

```text
z(0)+KF = −b∫₀ᵀ exp(−λt)u(t)dt
|u(t)|≤U  ⇒  |z(0)+KF|≤|b|U(1−exp(−λT))/λ = R_inf
```

对该单一标量、自由可选有界输入、无其他约束的模型，这个区间条件是可达条件。它不要求拟合E_b。但实际中层只能改参考，真实转角速率还受ECBC/ESO/local300、转角幅度、执行器动力学、路径需求影响。配置±3rad/s是最终执行器速度命令限幅，并未证明实测δdot硬限幅正好3，因此不能直接称整车可恢复区域。

L2预算给半径 `R_2=|b|sqrt(E_b(1−exp(−2λT))/(2λ))`。等半径换算得到

```text
U_equal = sqrt(E_b λ/2 × (1+exp(−λT))/(1−exp(−λT)))
```

用已有24个快照的λ=6.38450585、E_b=.0308390853、T=1s，`U_equal≈0.31429rad/s`。但这不是L2最小能量最优输入的峰值；后者在边界初时刻为

```text
|u*(0)| = sqrt(2λE_b/(1−exp(−2λT))) ≈ 0.62752rad/s
```

两者都小于3，但只能说明所拟合任务代理对应较小的理想控制努力尺度，不能据此证明“闭环带宽就是0.314”或“其余物理能力可调用”。数值与24个状态的来源见[输入换算审计](evidence/tolerance_review_audit_20261022/equivalent_input_audit.json)。同时需说明力与控制可同时作用、T≥Δ、γ视作常数等假设。

## 四、建议采用的优先顺序

1. **先把恢复数据密度和任务保持问题做成可控实验。** 用TRAIN实际前缀完整分支、3–4s恢复片段，保留名义父策略BC/KL或适量无扰回合。短片段价值边界和完整任务剩余时间必须说清；前缀采集、失败和训练成本一并计。先验证有实际恢复暴露且正常任务不明显退化，再讨论容扰度引导增益。critic预热作为单独工程验证，不把未证主因写成事实。
2. **引导效用与控制器改进分层比较。** 从同一固定父模型、相同奖励/优化设置出发，比较uniform与guided，记录状态条件余量/选择概率/实际活动恢复样本；保留覆盖而非直接只练最低30%。最终至少多训练种子、独立场景组。若采用u325/V3，明确是新控制器协议，不与旧双端点直接混算。
3. **解析余量继续做可解释基线，而不是先验安全判定。** 增加输入幅值约束版与经验方向标签比较；先检验单调性再细化边界。 learned predictor或余量特征应在足够独立TRAIN标签后再做匹配消融，不因解析代理表现差立即增加第三个网络。

不一次性同时改V3铰链、成功阈值、初态随机化、critic、引导强度和预测网络，否则又无法知道哪个改变有效。没有证据要求我们先把容扰度精度做到极高；真正要验证的是训练用途。

### 7.2 任务判断：存在需验证的风险，不能据此宣判路线错误

1. **冻结底层是研究问题的控制条件。** 当前问题是“共同冻结local300时，上层可否改善任务恢复，以及容扰度引导是否比均匀采样有用”。联合训练底层会变成另一问题。50Hz在0.1s中有5次动作；转向参考修正限速0.8rad/s，对应0.1s最多0.08rad，约4.6度，滤波时间常数0.08s。权限有限但不是零。必须测真实响应、饱和和失败时序，才能断定上层无改善空间。历史864例评测所有组均无physical_failure，主要差异是任务保持/路径域，不能据此说6–8N已超出内环物理稳定域。
2. **第0步不能预知随机力是合理的因果任务。** 相同已知状态面对尚未出现的不同力，部署策略本来就应先做相同动作，然后依据姿态、角速度、历史和ESO特征反馈；这不是要求“盲猜”才能成功的bug。Actor已有反馈历史和ESO派生特征，不等于受扰后仍看不到任何信息。随机延迟0.2–0.5s仍无法让Actor预知随机符号，且降低每段的恢复暴露密度。延迟可用于时刻泛化消融，不能当作消除部分可观测性的修复。
3. **Asymmetric Critic值得作为候选，不是必然修复。** 当前Critic确实不知脉冲计划，初始价值学习条件期望并无错误。加真实力/剩余冲量可能降低价值误差或优势方差，但是否改善策略需配对实验。它会改变352维Critic、初始化和checkpoint合同，必须独立版本，Actor保持部署反馈。只输入当时真实可定义的训练特权量；不声称知道未来随机力是部署能力。
4. **关闭tolerance奖励是为了识别采样效用。** 早期无真实脉冲的shaping未显示一致收益，解析代理跨速度有false-safe；先固定原奖励比较uniform/guided是合理控制变量。若同时改奖励，就无法把收益归因于容扰度采样。4s片段解决每20s只有一次扰动的稀疏暴露问题，不代表抛弃容扰度主线。
5. **“四重枷锁锁死Actor”缺乏证据。** KL只在约4万名义父策略anchor上计算，不是在每个受扰状态强行复制父动作。系数0.05的强弱取决于实际KL和梯度，不能凭系数定性。当前父actor_lr是1e-4，3e-5是降为30%，也不是所称“减半”。最近α0最终u27两组均接受16/16minibatch，Actor梯度范数约0.74–0.75，非零；名义anchor KL约0.0012–0.0016。25是25个rollout更新，每轮4epochs×4minibatches，并非25次梯度步，2轮critic-only另计。这里只能否定完全锁死，不能证明约束最优或25轮充分。
6. **恢复与路径目标可能冲突，但惩罚强弱要看数据。** 最近α0 u27偏移幅度成本约0.0013、变化率约0.0185、路径约10.8–11.1；不能称偏移惩罚“严厉到无法动作”。滚转、工作滚转、滚转速率和终止惩罚也已存在。路径压力过大仍是合理假设；近期α1 u17域退出24次/轮、physical0，Critic loss约6万，说明需要关注任务/值拟合，尚不能确定是力标签缺失、奖励还是状态分布。按真实受扰标签在0.5–1s内切换奖励还引入Actor未显式观察的奖励阶段；应先尝试可观测姿态/误差触发的平滑权衡，独立消融，而非直接多项同时改。
7. **硬编码配置校验的工程批评成立。** 历史精确值用于防止已命名协议被静默改写，不证明这些值合理或最优。后续新协议应由版本化配置表达seed/budget/LR/KL/窗口参数，校验结构、范围和已冻结manifest；不能通过删除校验让旧run身份容纳新算法。本轮性能补丁保留已运行协议，不改预算、种子或奖励。
