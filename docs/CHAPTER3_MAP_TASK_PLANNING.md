## 数据结构

- `MapGraph`：`map_id`、物理资产及身份、`regions`（区域ID/几何）、`connections`（有向连接、参考路径资产、弧长区间、道路半宽、适用技能、最晚分流位置）、`skills`（控制器及精确策略身份）。不保存整条任务程序。
- `Task`：起点区域、目标区域、有序必经区域、必需技能、禁止连接、物理协议ID和约束。任务由外部用户给定；模型不能改目标或放宽约束。
- `TaskPlan`：`map_id`、`goal_region`、有序`steps`，每项为`target_region`与`candidates:[{connection_id,skill_id}]`，以及与Task相同的`hard_constraints`。候选和任务顺序可改，但不能添加速度、alpha、电机命令或外部路径。
- `CapabilityQuery`：plan、已完成段、实测状态及时间、当前位置/区域、剩余准备距离、累计路廊违反、当前可用连接。
- `CapabilityReport`：逐候选`feasible/infeasible/unknown`、预测完成代价及单位/来源、未满足条件、证据身份、内部执行指令、测量来源/查询耗时。内部指令不由LLM填写。只验证已有实测状态对应的当前段，未来段标记pending，不能把当前姿态复用成未来真实状态。

`feasible`仅表示在冻结经验模型和声明硬约束下得到支持，不是安全证明。无证据、未知技能身份、无法预测代价必须明确未知；几何可达不等于动力学可行。
