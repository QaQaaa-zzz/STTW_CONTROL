整车过岸按每个 5 ms 位姿计算各碰撞原语在世界 x 方向的最小投影。逐例 CSV 也保留没有首触记录的轨迹。就全部 36 条而言，Source 有 10 条、Full RB 有 2 条至少一次双轮同帧远岸且两轮在末子步有正载荷；Full RB 两次各仅覆盖两个 5 ms 采样帧，均未通过回正阶段姿态、侧倾角速度与前进速度要求。三条代表轨迹的接触、中间帧及实际终止见[两轮短时承重一](rb_run1_route4_h75_v2_contact.jpg)、[短时承重二](rb_run1_route6_h75_v3_contact.jpg)和[首触后无双轮承重](rb_run1_route0_h75_v0_contact.jpg)。唯一成功交回的 Source 于 6.855 s 接管，最终 y = −0.601 m，由 tracking_domain_exit 终止。

**原训练域与本图入口。** 原 rb_run1 的冻结训练配置以 stable_forward_recovery 为成功定义，从完整起点、当前 teacher 快照和历史成功快照混合训练。本图以 x = 8.55 m 作为请求切换阈值，距真实近岸 1.75 m；跳跃网络实际接管与物理卸载另记。接近阶段由 H75 闭环产生，地图使用 implicitfast、摩擦配置 0.8、关闭 native_wheel_contacts，并增加沟、平地缓冲及真实落地后锁摆交回。冻结模型、归一化器与动作顺序可从声明回溯。72 条采用同一触发设置，未做触发位置、进沟状态和接触设置的单因素对照，因此可以定位失效发生在唇口附近和交回前，尚不能判定是哪一个域差导致；24 条的接触记录也不足以解释全部 30 条。Phase 4 公平接口仍须同域实测。

### 宽沟上的同入口核对

[0.45 与 0.55 m 共 168 对逐例结果](wide_skill_pairs.csv)。从既有触发距离筛查读取原 Source 和原 Full RB Run 1 的全部记录。每个沟宽各 84 对，每一对从起步到 Source/Full RB 接管帧的 qpos、qvel、地面控制历史均逐元素相同；同一沟宽的地形二进制、XML 和生成源数据均逐字节相同。两套技能共用名义工况。把 Source 换成 Full RB，按同一命令配对计数如下。

| 沟宽 | 事件 | 新增 / 保留 / 丢失 |
|---|---|---|
| 0.45 m | 核验飞越 | 7 / 7 / 14 |
| 0.45 m | 飞越后双轮承重 | 2 / 1 / 9 |
| 0.45 m | 锁摆交回、终点保持 | 两项均 0 / 0 / 0 |
| 0.55 m | 核验飞越 | 1 / 0 / 3 |
| 0.55 m | 飞越后双轮承重 | 0 / 0 / 1 |
| 0.55 m | 锁摆交回、终点保持 | 两项均 0 / 0 / 1 |

原 Full RB 在部分配对中确实增加了飞越，但这些新增没有延伸到锁摆交回。早先 0.3 m 的唇口故障见上文。此表量化名义物理事件与原路线终点，主动施加扰动的贡献、合法驶离集合及在线规划是否选中仍待验证。
