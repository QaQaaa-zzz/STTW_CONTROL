## 先限定我们的主张

我们的实际对象是固定学习底层与有界参考接口组成的闭环，中层输出参考修正而非电机动作。alpha表示路径—速度偏好，当前物理价值头只估计既定训练分布下有限窗无触地结局，没有力幅查询输入。偏好、参考、进入状态和方向性抗扰能力互相影响，是研究问题；任何单个已有模块都不因此成为新方法。

第16–19批训练非零样本70→77/96、7增0失只支持继续固定阶段。7例都在低速右弯，退出任务域后使用held-reference尾；它们不是完成原路径、同一受扰瞬间的切换救回或独立终点证据。现有普通续训、zero和简单参考规则仍是必要对照。

## PPO裁剪选择：明确现有算法，不修改当前训练

PROMO附录D-B提醒的标量化顺序问题适用于检查算法定义。我们的现有实现对原任务和物理优势分别构造PPO裁剪项，再加权；不是先相加优势再只裁剪一次。这是已声明的代理目标选择，并非看到另一篇文章采用不同顺序就必然是代码错误。

以下是对本项目公式的直接代数核对，非原创理论主张。令同一动作概率比为r，截断值为c，两个冻结且已按本项目规则定标的优势为a和b，物理系数beta非负。定义f(x)=min(r*x,c*x)，则：

```text
separate = f(a) + beta*f(b)
combined = f(a + beta*b)
combined - separate = |r-c| * min(|a|, beta*|b|),   a*b < 0
                      0,                           其它情况
```

理由：正优势乘min(r,c)，负优势乘max(r,c)；同号时线性，相反符号时只需按a+beta*b的符号分两种情况。因此分项代理不会高于合并代理；未发生概率比裁剪或两项同号时相等。两种算法的归一化若不同，不可再套用这个相同尺度比较。

只读原第3和19批物理臂的实际post-4epoch native与原采样数据，核对SHA/fingerprint；没有优化、改权重或重跑物理。结果见[原始核对](/home/qy/STTW_CONTROL/runs/worktrees/tolerance-calibration/runs/online_survival_clipping_review_u19/results.json)：
