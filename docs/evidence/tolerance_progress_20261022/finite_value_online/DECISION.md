# 三臂64轮固定终点：结果与路线裁决

2026-10-26；STTW_CONTROL；一次匹配训练比较、两条旧路线的相关开发分支，不是独立最终测试。

先看[左路全部150条实际XY](../../../../runs/finite_value_online_v1_recovery55_fixed64_evaluation/analysis/all_xy_left.png)、[右路全部150条实际XY](../../../../runs/finite_value_online_v1_recovery55_fixed64_evaluation/analysis/all_xy_right.png)与[原alpha名义代价—受扰表现](../../../../runs/finite_value_online_v1_recovery55_fixed64_evaluation/analysis/nominal_cost_vs_disturbed_outcomes.png)。参考为原固定路径；星号是任务目标，轨迹仍继续到原10秒。全部方法、五alpha及已声明事件均保留。

## 为什么做、具体怎么做

上一轮排查发现Critic的末段价值预测严重失配。本实验检验纠正这种数值行为是否真正改善控制，而不把RMSE改善当成抗扰效果。三臂共用原task64 Actor、隐藏Critic、逐点相同初始价值函数−.16D、原V3奖励和有限参考权限；冻结ECBC、ESO、local300、物理和执行器。D=(1−.997^(500*remaining_fraction))/(1−.997)。

- free_GAE：自由残差价值NN−.16D，GAE lambda=.99。
- finite_GAE：有限剩余时域非正价值−D softplus(NN)，lambda=.99。
- free_MC：自由残差价值，lambda=1；同时改变优势和价值目标，不称为纯Critic消融。

每臂64批×60个完整10秒回合，前2批Critic-only、后62批更新Actor，每批4epoch；Actor学习率1e−4、Critic3e−4。固定final64，不选最佳中间点。主机重启与磁盘中断只属于同一实验的工程接续，不算独立重复。

终点评价为50共同事件×6角色=300条确定性均值Actor轨迹。两条左右R1.1旧路线，请求速度1.8/1.5m/s，原alpha=0/.25/.5/.75/1；每组零力与正负32N两次预先抽定起扰时刻，持续.1秒，起扰窗口1.6–3.4秒。三个基线分别为原父策略、当前侧倾角速度触发的原有短时速度支持、原有全程速度支持；控制器不知道本次未来起扰时刻/方向。

三臂最终Adam计数各[248,256,256]。训练有效实际22,610,292/分配23,040,000个5ms lower步，另保留失败部分108,000，已记录总22,718,292/23,148,000；重启前未落盘额外成本UNKNOWN。评价实际/分配600,000 lower步，0optimizer。物理积分器更细子步不与这些控制步混称。

## 固定终点结果

任务是整窗不触地、通过原目标并满足原末1秒保持要求；与单独防摔分开。

|方法|无扰任务/10|受扰不摔/40|受扰任务/40|合计任务/50|无扰平均原alpha成本|受扰平均成本|
|---|---:|---:|---:|---:|---:|---:|
|父策略|8|40|11|19|19.613|89.223|
|父策略＋因果短时支持|8|40|11|19|19.613|78.243|
|父策略＋全程支持|4|40|6|10|46.552|75.980|
|free_GAE|2|40|2|4|23.080|68.136|
|finite_GAE|6|40|3|9|24.215|69.837|
|free_MC|8|40|6|14|19.451|69.639|

全部300条未触地、0UNKNOWN，全部脉冲暴露核验通过。**这批面板对防摔已饱和，不能据此排名抗摔能力，也不推翻旧力档扫描中的真实触地结果。**

相对父策略，free_GAE任务0新增/15丢失，finite_GAE为1新增/11丢失，free_MC为2新增/7丢失。finite_GAE对free_GAE有8新增/3丢失，但对free_MC为0新增/5丢失。因此只说结构优于普通GAE会遗漏更强的MC对照。MC保留全部无扰任务标签，但受扰任务仍弱于父策略，不采用为新最终策略。

原因果支持对父策略任务2新增/2丢失，合计不变；平均受扰成本下降约12.3%，路径RMSE均值1.273→1.015m。它是值得保留的简单基线，尚不是学习方法独有增量。三个训练臂也降低了受扰平均成本；这些真实连续收益保留，不把“任务计数未提升”写成“所有指标都变差”。

成本和共同任务保持不是同一目标。50个事件中22组至少有一个已测存活任务成功候选；其中最低原alpha成本候选17组成功、5组失败。这个六候选库的事后诊断不是全局最优、不是可部署选择器，也不证明奖励必然错误。不能为了让表格好看而更改alpha或放宽原标签。

## 下一问题的只读证据

额外脚本[review_endpoint.py](review_endpoint.py)只读已有数据：逐一复核父因果支持原始SHA，按真实XY和原路径重算几何误差，读取最后一次实际支持结束时的状态。0新物理、0optimizer；[完整结果](../../../../runs/finite_value_online_v1_recovery55_fixed64_evaluation/analysis/decision_review.json)、[逐例交回记录](../../../../runs/finite_value_online_v1_recovery55_fixed64_evaluation/analysis/causal_release_review.csv)。

50条父因果策略中39条实际触发支持；其中29条最终任务失败。29条在最后支持结束时侧倾角速度都已在原有.4rad/s退出阈值内，但全部仍在原路径/航向/速度联合带外。绝对路径误差中位数.578m、航向误差.458rad，剩余时间中位6.2秒。这支持“角速度安静不足以表明任务已能接续”的描述，不是稳定性证明，也不证明换一个交回时刻就能成功。

特别保留反解释：这29条中20条在支持结束后仍有Actor不可查询的时段；合法比例中位.744。因此不能把全部失败归因于合法Actor自身不会恢复，当前域退出/重入过程也需解释。

源码核对发现**现有名义参考已经包含Pure Pursuit路径反馈**（path_reference.pursuit），并非缺少路径反馈；进入几何非法域时Actor被屏蔽，live原路径参考仍推进（anticipatory_reference.make_reference_step）。所以“再加一个普通路径反馈”不能直接当成新方法。右路alpha.75的零力轨迹本身就有明显持续摆动，说明并非所有问题都由受扰或交回造成。

## 裁决与下一步

1. 关闭本次价值结构路线的加训/调参：没有超过普通MC及父策略的联合控制结果。保留三臂、父策略、因果支持全部权重及来源，不更新已采用指针，不复活旧解析容扰公式拟合。
2. 接下来做一个有界的任务接续机会诊断：先核对名义Pure Pursuit、实际下层转向响应及域退出/重入的关系，再决定是否值得从同完整状态比较原控制、继续支持与简单可执行几何调整。必须通过原速度/转角参考、滤波、限幅和变化率接口，不能直接改电机动作或拼接状态。当前只读诊断已完成，尚未启动新的尾段物理实验。
3. 只有可执行候选确实存在改进空间，才研究偏好兼容的接续/参考选择；简单规则覆盖收益则保留简单解释。后续新情境仍须包含旧的实际触地分支或预先独立声明的挑战条件，不能仅在本轮全存活面板上声称抗扰增强。

研究中心仍是冻结底层与有限参考权限下，用户偏好、任务代价和实际抗扰能力的协调。本轮提供路线排除和机制线索，不是Transactions论文已经成立。旧E_min=(z+KF)^2/W未用于本轮控制，终端自由输入努力不等同闭环整窗防摔能力。
