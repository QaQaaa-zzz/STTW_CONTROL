# 重规划以后，“路径优先”在评价什么？

2026-10-27。状态：数值诊断可附限制分享；主偏好效用定义待用户答复。0新物理、0训练、0优化、0新阈值。原目标1m首达和整窗不触地仍独立保留，不受本次语义问题影响。

## 为什么做、什么尚未决定

重规划改变了跟踪路线。α0可以理解为“仍尽量贴原路线”，也可以是“跟好新的可行路线”；两者不等价。用户已允许受扰后去原目标的新路线，故不能擅自把原路线偏离升级为任务失败；也不能只因新路线从当前位置开始、误差变小，就宣称原偏好得到改善。

已通过异步选择题询问用户并调用Bark：重规划后优先跟新路线、仍贴原路线计绕行代价，还是暂以到达防摔为主。当前尚未收到答复；不将推荐项或等待时间当答案，不选择标量总效用或恢复scenario搜索。

## 条件和具体做法

复用既有72条：两路线、两α、0/±32N、current64/H75/zero及原路/重规划，最多20s，完整条件见REPLANNING_HEADROOM_REVIEW.md。每条原raw和原path SHA核对；首达/触地窗口沿已认证结果，不再改终点标签。

新`review_replanned_preference_scope.py`并列保存：

1. 原路线：用实际XY/yaw，从实际初始qpos[:2]出发，按原局部有界、单调几何投影逐tick重建ey/航向误差。它只是shadow评价，不是让旧控制器重新执行。实际初始projection均0。**不能用物理bookkeeping reference_pose当实际初始位置**，本组两者相差约3m；原代码RecoveryEnv.pose明确用qpos[:2]。
2. 执行路线：直接保留raw中实际当前路径的ey/航向误差；重规划前后其几何对象可以不同。
3. 速度：实际速度对原用户请求，不把加速参考当用户请求。
4. 参考变化：实际governed速度/转向参考的总变差TV，含初始governor.current_reference到首个发布值。分别保留m/s和rad，不用任意尺度相加，也不称电机能耗或控制能量。

每条连续指标止于自己的首次到达、触地/故障前或20s中最早者；成功首达当步纳入，触地当步不纳入。失败短前缀不能称更便宜的完成。全部72奖励有效标记均覆盖实际执行步，未使用旧held尾的陈旧误差。

第一版只比较NN/replan与zero/original；随后保留第一版，补上双方同规划规则的zero/replan强对照，最终v2共8组。**同规划规则不等于两者执行同一条几何路线**：进入状态、触发时刻和新路都可不同。

## 误差跳变的具体例子

zero左弯α0/−32N在5s重规划附近，原raw上一tick ey约−1.0975m，下一tick新路ey约+.0010m；车这5ms实际只移动.0054m。同一个下一tick姿态按原路线算仍约−1.1009m。通俗说：**车没有瞬间移回原路，而是规划了一条从车当前位置出发的新路。**这可以是合理的任务接续，但误差读数下降不能独自证明物理恢复。

16个实际切换中，5ms XY步长最大.00693m，相邻raw ey跳变最大1.591m，同posttick姿态按原/新路的ey差最大1.596m。后续真实运动也会被规划改变，不能把整段运动差异全叫测量伪影；原goal到达增益不因此被撤销。
