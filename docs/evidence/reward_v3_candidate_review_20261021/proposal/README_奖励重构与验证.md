# STTW 单网 α 奖励重构：全程偏好，而不是出弯后取消偏好

## 交付结论和证据边界

推荐候选版本：`path_persistent_preference_v3`。一个 Actor 接收 α，一个 Critic 接收 α；不使用两个 Actor，不模仿两套旧策略，也不平均两个网络的动作。旧双网仅提供固定物理轨迹作为奖励偏好锚点。

已完成：核对固定提交的 JAX 奖励、NumPy 重建、观测、训练接口、审计脚本和结果；对历史四组转弯的已发布分项积分做精确代数变换，得到新奖励的20个五α全回合差值；运行10,000个人工状态上的机制/回归检查及JAX JIT数值检查，共22项检查通过。

## 1. 真实基线

固定提交：`7cea794cb4342ba83377f9de496e593846133a7c`。

审计的实际manifest未填写 `reward_version`，运行历史Coverage公式。代码支持显式v1/v2，但不能把已存在的代码分支当成实际运行版本。实际侧倾权重80/240，起罚阈值0.26/0.30rad，成本上界8980.2，奖励按 `-0.1 * 0.005 * cost_rate` 对每个5ms底层tick积分。PPO折扣每20ms使用γ=.997。

旧路径权重：`10 - 9 χ α`。旧速度权重：`10 - 9 χ (1-α)`。因此χ=0时，两个端点都恢复路径权重10，α在直线和恢复段失效。不存在一个独立的、叫作“恢复惩罚”的成本项；出弯恢复的代价主要是持续的普通路径/航向误差成本。不能凭旧讨论虚构当前成本项。

## 2. 新奖励的完整定义

记 H(x)=x²（|x|≤1），否则H(x)=2|x|−1；注意不是另一种带1/2系数的Huber定义。

定义：

- `p = H(ey/0.1) + 0.5 H(eψ/0.1)`。
- `v = H(ev/0.1)`，其中 `ev = actual_forward_speed - v_user`，绝不对减速后的governed参考计算这个目标误差。
- `qp = H(max(|ey|-0.10,0)/0.10)`。
- `qv = H(max(|ev|-0.05,0)/0.10)`。

先构造、限顶端点成本通道：

```
P  = min(10 p, 200)
V0 = min((10 - 9 χ) v, 200)
V1 = min(10 v, 200)
Q0 = min(20 χ qp, 400)
Q1 = min(20 χ qv, 400)
CP = P + V0 + Q0
CV = 0.10 P + V1 + Q1
Cα = Ccommon + (1-α) CP + α CV
r_tick = -0.1 * 0.005 * Cα
```

`Ccommon`为现有七项共同成本（分别按原cap限顶）：

```
roll             = min(80 H([peak_roll-.26]+/.04), 1800)
working_roll     = min(240 H([peak_roll-.30]+/.02), 6000)
roll_rate        = min(H([|phi_dot|-.8]+/.8), 40)
overspeed        = min(2 H([ev-.05]+/.1), 160)
low_speed        = min(4 H([1.5-v_actual]+/.2), 160)
offset_magnitude = min(.02 sum((offsets/[1,.2])²), .2)
offset_rate      = min(.03 sum((20ms_endpoint_rate/[1,.4])²), 20)
```

路径与航向误差一起进入同一偏好通道，不能只减小横向成本而把航向成本恢复为高权重。安全、超速、低速、执行器平滑成本不乘α，不因保速偏好而放宽。

重要：此版明确采用“端点成本通道先cap，再进行非负凸组合”。这不是旧函数先混合原始成本再cap的同一表达式，特别是中间α、发生饱和时两者可能不同。必须作为新版本独立实现、单独记录cap触发，不能静默改变旧版本。这里平均的是同一次实际状态/动作上的目标成本，不是两个策略的动作或两条反事实轨迹。

### 出弯后会怎样？

χ回到0时，α0仍按路径10、速度10控制；α1仍按路径1、速度10控制（未触及cap时）。α1没有失去偏好，但路径成本也没有消失。相同速度和安全条件下，回线早于永久偏离始终有更高奖励。以ey=.30m、航向和速度误差为零为例，α1仍每秒损失0.5奖励，不存在偏离免费。

这不是保证任意策略必在给定秒数内回线的数学约束。目标截面到达、最后1秒速度/路径/航向保持、物理和路径域失败继续作为资格条件，不能用高总奖励替代。不将0.40m诊断阈值偷偷升格为硬走廊：已认可左2.6m/s轨迹的弯内路径RMSE约0.458m。

本版不增加恢复计时器、不增加临近回合末的权重突变，因此不要求修改351维Actor/352维Critic。当前Actor不含回合剩余时间，Critic才含；若将来引入时限型恢复奖励，必须同步处理Actor的可观测性。

## 3. 已完成的真实数据验证

A=历史α0轨迹；B=历史α1轨迹。所有差值均为B−A，正数表示偏好保速轨迹。

| 场景 | 旧α0 / 新α0 | 旧α1 | 新α1 |
|---|---:|---:|---:|
| 左 R2、2.0m/s | -14.146623 | -12.823604 | +2.296909 |
| 右 R2、2.0m/s | -10.085393 | -9.393811 | +0.505642 |
| 左 R2、2.6m/s | -57.941139 | -23.820540 | +10.346100 |
| 右 R2、2.6m/s | -27.600229 | -8.227584 | +4.224371 |

计算不是从RMSE猜回报，而是使用已发布的逐项奖励积分：

```
Gnew(0) = Gold(0)
Gnew(1) = Gold(1) - Gpath_old(1) + .10 Gpath_old(0)
Gnew(α) = (1-α) Gnew(0) + α Gnew(1)
```

每条式子都针对同一条固定物理轨迹。失败尾罚是相同公共项，线性组合不重复扣罚。

这四组是已用于开发的校准案例，不是独立测试集，不能据此声称泛化或PPO训练成功。尤其α1右2.0m/s的正裕度约0.506，较小，折扣复核不能跳过。

路径次要系数的敏感性：ε=.05、.075、.10、.125时，四组α1全回合排序均正确；ε=.15时右2.0m/s不再通过。ε=.10保留已有强冲突区1:10的基础偏好量级，也留出一定余量。不是声称该值最优。

在这四组既有行为之间，新回报随α是精确线性的，但旧两条轨迹的排序交点约为α=.85～.95。它不意味着α=.5必然产生“半减速半外扩”，也不意味着中间α条件策略已经验证。训练后必须评估实际误差-α曲线，不能把离线奖励直线当作策略连续性证据。

## 4. 上界与失败语义

共同成本cap总和8180.2；α0端点总cap8980.2；α1端点总cap8800.2。因此原全局8980.2仍为保守上界，无需为了本版重算一个更小失败尾罚。

```
Rfailure(N) = -5 - .1*.02*8980.2*(1-.997**N)/(1-.997)
```

沿用原真实失败区间替换语义：失败20ms区间的正常tick奖励必须清零，只在终点记一次尾罚。不能把正常成本和尾罚双算，不能伪造剩余轨迹。工程故障继续报错，不作为可供学习的“坏策略”。

## 5. 课程学习

奖励在各难度阶段固定，不每次升级重新调权重。全程采用reset采样40% α0、40% α1、20% U(0,1)，每回合α固定，路线抽样独立于α。左右弯均衡，新阶段保留20%～30%较容易场景的新交互样本，不把旧PPO轨迹直接作为当前on-policy数据。

| 阶段 | 请求速度 | 半径 |
|---|---|---|
| 基础 | 2.0–2.4m/s | 2.2–2.6m |
| 出现取舍 | 2.4–2.6m/s | 2.0–2.2m |
| 加强取舍 | 2.6–2.8m/s | 1.8–2.0m |
| 当前高难度 | 2.8–3.2m/s | 1.6–1.8m |

上述范围来自用户课程图，是待验证的起点，不是已完成的训练结果。阶段内先小幅增加速度，再减小半径；按同一检查点的安全、完成、保持及冲突段端点表现升级，不按轮数或总reward升级。

不要求简单阶段刻意制造α差异。在明显冲突阶段，分别检查α0是否靠合理减速改善路径、α1是否保速且最终回线；同时具备更好路径和速度的策略不应因“差异不够”被判差。不能把高难度policy1仅凭命名当成应该获奖的保速行为。
