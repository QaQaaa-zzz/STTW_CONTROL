# Online preference–physical-credit matched continuation

Status: design for the next implementation, not a launched run. The preceding engineering and12-case evaluation are complete; no current efficacy training is running.

## Question and evidence motivating this step

One shared4-episode batch and4 PPO epochs per arm changed weights and improved one nominal trajectory, but all three models still survived3/4 cases, disturbed1/2, and no paired contact outcome changed. Physical-credit did not outperform ordinary task continuation. This is an early no-increment result, not evidence of convergence or proof that more training will help. The existing task Critic has large distribution/terminal-contract mismatch; a real repeated on-policy comparison is needed before adding methods or rejecting the idea.

The scientific object is finite-window contact avoidance under a declared disturbance distribution, together with retained alpha preferences. A physical value baseline predicts survival under that distribution and current composite policy. It has no force-query input and must not be called a Newton-valued tolerance predictor. Directional tolerance is subsequently characterized with measured force–contact curves, not inferred by thresholding this scalar Critic.

## Evaluation and decision

Freeze the terminal update64 models; do not select the winner on a reused panel. Compare parent/task-only/physical-credit using matched new-noise per-alpha trajectories, report paired contact gains/losses, actual pulse exposure, domain hold and original task/speed/path costs. Reuse existing nominal preference cases to test whether alpha retains useful behavior; do not infer continuous-alpha behavior from alpha0 alone. Add broader confirmation only after a useful development effect exists; keep train/dev/test provenance explicit.

Success need not mean all cases survive or zero task cost. An added-credit contribution requires a useful measured physical gain with its costs exposed. If task-only obtains the same benefit, do not credit the physical term or manufacture a new module. If effects remain absent despite actual learning/exposure, stop this route rather than explain every result as undertraining. Task-specific/system novelty still requires stronger evidence and eventual deployment validation, not a renamed loss.
